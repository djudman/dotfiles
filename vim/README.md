# Vim / Neovim

Своя светлая схема, общий конфиг для vim и nvim. Рассчитано на стандартный
`/usr/bin/vim` (macOS) и `nvim`, без внешних наборов схем.

## Файлы и симлинки

| Файл | Назначение |
|---|---|
| `vim/vimrc` | сами настройки, читаются и vim, и nvim |
| `vim/.vimrc` | короткий загрузчик: `source ~/.vim/vimrc` |
| `vim/colors/minimal.vim` | цветовая схема `minimal` |
| `~/.vimrc` | симлинк на `vim/.vimrc` (для vim) |
| `~/.vim/vimrc` | симлинк на `vim/vimrc` (общий файл настроек) |
| `~/.vim/after` | симлинк на `vim/after` (дополнительный синтаксис) |
| `$XDG_CONFIG_HOME/nvim/init.vim` | `source ~/.vim/vimrc` (для nvim) |

```sh
mkdir -p ~/.vim
ln -sfn ~/github/dotfiles/vim/.vimrc ~/.vimrc
ln -sfn ~/github/dotfiles/vim/vimrc  ~/.vim/vimrc
ln -sfn ~/github/dotfiles/vim/after  ~/.vim/after

# init.vim кладётся в каталог конфига nvim (по умолчанию ~/.config/nvim)
NVIM_CFG="${XDG_CONFIG_HOME:-$HOME/.config}/nvim"
mkdir -p "$NVIM_CFG"
printf 'source ~/.vim/vimrc\n' > "$NVIM_CFG/init.vim"
```

`~/.vim` нужен реальным каталогом: в нём же лежит `bundle/` с плагинами Vundle,
поэтому внутрь ведут симлинки, а не весь `~/.vim`.

## Плагины (Vundle)

```sh
mkdir -p ~/.vim && git clone https://github.com/VundleVim/Vundle.vim.git ~/.vim/bundle/Vundle.vim
vim +PluginInstall +qall
```

Ставятся `VundleVim/Vundle.vim` и `tpope/vim-surround`. Набор схем плагином
не тянется — используется своя (`vim/colors/minimal.vim`), поэтому конфликтов
одноимённых схем нет.

Блок Vundle в `vimrc` обёрнут в `isdirectory('~/.vim/bundle/Vundle.vim')`: без
клонированного Vundle конфиг продолжает грузиться, просто без плагинов.

## Схема `minimal`

Белый фон, чёрный текст, минимум цветов:

| Элемент | Цвет |
|---|---|
| зарезервированные слова, операторы, встроенные имена (`int`, `str`, `len`) | синий `#0000c0` (27) |
| строки и символьные литералы | зелёный `#008700` (28) |
| числа, `float`, `boolean` | фиолетовый `#7f00af` (91) |
| комментарии | серый `#9e9e9e` (247) |
| `TODO:` / `FIXME:` в комментариях | тот же серый, **жирный** |
| имена функций и методов, вызовы `__init__`, имя декоратора | тёмный magenta `#af00af` (127) |
| сам `@` декоратора, имена исключений (`ValueError`) | чёрный, без выделения |
| имена классов и структур | чёрный, без выделения (как обычный текст) |
| `self`, `cls` | как зарезервированные слова, `#0000c0` |
| переменные, типы-значения, прочее | чёрный (как обычный текст) |
| номера строк | `#bcbcbc` (250), текущая — жирный чёрный |
| строка под курсором | `#f2f6ff` (189) |
| вертикаль на 80-м столбце, строка состояния | `#e8e8e8` (255) |
| разделитель окон | `#dadada` (253) |
| поиск / инкрементальный поиск | фон `#ffffaf` (229), чёрный текст |
| выделение, `MatchParen`, выбранная строка меню | чёрный/белый текст на синем `#0000c0` |
| `diff` | `+` зелёный, `-` серый, изменённое — синее/фиолетовое |
| орфография (`SpellBad`), `ALEInfo` | подчёркивание серым / синий |

Особенности реализации:

- Каталог схемы конфиг вычисляет из собственного пути (`resolve('<sfile>:p')`
  разворачивает симлинк `~/.vim/vimrc`), поэтому расположение репозитория нигде
  не зашито: работает и `~/.vimrc → vim/.vimrc`, и `source .../vim/vimrc`
  напрямую, и клон в другом каталоге.
- Схема добавляет каталог `vim/` в `runtimepath` и переустанавливает себя на
  `BufReadPost`/`Syntax`/`FileType`: `syntax reset` при смене синтаксиса сбрасывает
  цвета, иначе схема «пропадает» после открытия файла.
- В схеме заданы и `cterm*` (индексы xterm256), и `gui*` (hex) — работает
  в терминале любого типа. При `termguicolors` применяются hex-значения.

## Что включено в `vimrc`

- UTF-8 + `cp1251` в `fileencodings`, табы — 4 пробела, `autoindent`/`smartindent`.
- Поиск: `ignorecase` + `smartcase`, `hlsearch`, `incsearch`.
- `number`, `ruler`, `colorcolumn=80`, `wrap`/`linebreak`, `hidden`, без swap/backup.
- `scrolloff=0` — окно не прокручивается ради отступа при выделении и переходах
  к краям файла.
- `cursorline` — подсветка текущей строки, только в активном окне
  (`WinEnter`/`WinLeave`).
- Строка состояния (`laststatus=2`): имя файла, ветка git, тип файла, кодировка,
  `[строка:столбец/всего]`, процент. Ветка кешируется по каталогу файла.
- `<leader>` — пробел; <kbd>Esc</kbd> снимает подсветку поиска; <kbd>Ctrl-N</kbd>
  и <kbd>Ctrl-P</kbd> — следующий и предыдущий буфер.
- Системный буфер: в nvim — `clipboard=unnamedplus`, в vim — внутренние регистры
  плюс выгрузка янка в буфер по `TextYankPost` (подробности в «Ограничениях
  терминала»); `mouse=a` с `ttymouse=sgr` (только vim) — прокрутка, когда тянешь
  выделение мышью за край экрана.
- Без звука и мигания (`novisualbell`, `t_vb=`), `wildmode=longest,list`,
  `showtabline=1`.
- Python: обрезка trailing whitespace при сохранении, `cinwords` для отступов,
  `comments=fb:-,fb:#,s1:#` — без этого `TODO:`/`FIXME:` не подсвечиваются.
- Цвет: `termguicolors`, если vim собран с этой опцией и `$COLORTERM` не
  перечит 24 бита (пустая переменная тоже подходит), иначе `t_Co=256`.
- Строки `let python_highlight_all = 0` и соседние — наследие старых
  `python.vim`: vim 9.1 и nvim 0.12 их не читают, встроенные имена размечает
  группа `pythonBuiltin` (схема ведёт её на `Statement`).
- `after/syntax/python.vim` — группа `pythonInitName` для `__init__`: штатный
  `python.vim` размечает только определения после `def`, а вызовы
  (`super().__init__()`, `Repository.__init__()`) остаются обычным текстом.
  Группа ведётся на `Function`, поэтому цвет берётся из схемы. Каталог `vim/after`
  попадает в `runtimepath` через симлинк `~/.vim/after` (см. таблицу выше).

## Ограничения терминала

- **Форма курсора.** Линия во вставке, блок в остальных режимах. В nvim это
  делает `guicursor`; терминальный vim его в TUI игнорирует (здесь — Apple
  `/usr/bin/vim` 9.1, сборка «Normal version without GUI»), поэтому форма задаётся
  последовательностями DECSCUSR: `t_SI` = `6 q` (неморгающая линия), `t_ti`,
  `t_EI`, `t_te` = `2 q` (неморгающий блок; `t_ti` нужен, потому что при входе в
  vim `t_EI` не отправляется). Работает в Ghostty и iTerm2, форма вне vim
  берётся из настроек терминала (Ghostty — `cursor-style`). Толщину линии задаёт
  терминал, в Ghostty — `adjust-cursor-thickness`; vim умеет попросить только
  форму. Блок в normal-режиме оставлен намеренно: курсор vim всегда стоит **на**
  символе, и блок над последним символом читается как «после конца строки», а
  штрих рисуется слева от символа и выглядит как «перед ним».
- **Цвет блока курсора.** В терминальном vim `hi Cursor` игнорируется: блок
  рисует сам iTerm2 (`Profiles → Colors → Cursor` / `Cursor Text`). Схема задаёт
  `Cursor`/`lCursor` белым на чёрном на случай, если терминал их использует.
- **Шрифт.** `guifont="JetBrains Mono":h17` действует только в GUI-версиях vim
  (MacVim, `gvim`); в терминале размер задаётся профилем iTerm2.
- **Системный буфер обмена.** Apple `/usr/bin/vim` 9.1 умеет только **читать**
  буфер macOS, запись в `+` не происходит вовсе, а системных провайдеров в этой
  сборке нет (`-xterm_clipboard`, `autoload/clipboard.vim` отсутствует). С
  `set clipboard=unnamedplus` из-за этого сломано копирование: весь yank уходит
  в `+` и теряется (`yy` ничего не копирует, регистры `"` и `0` не заполняются),
  а `p` читает `+` и вставляет то, что было скопировано вне vim. Поэтому в vim
  опция снята: `yy`/`p` работают по внутренним регистрам, `TextYankPost`
  выгружает янк в буфер через `pbcopy`, а из буфера берут явно — `"+p`.
  Удаления (`dd`) буфер не затирают. В nvim `clipboard=unnamedplus` оставлен:
  там синхронизация двусторонняя.
